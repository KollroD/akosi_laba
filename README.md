## ⚙️ Как это работает под капотом (Архитектура)

Обычные папки в ОС не имеют жесткого лимита на размер, поэтому утилита `df` (или командлеты в Windows) не могут показать «процент заполнения конкретной папки» - они показывают состояние всего жесткого диска. Чтобы обойти это ограничение и создать честные условия для тестирования, скрипт использует следующий подход:

**Linux (`log_manager.sh`)** сам создаёт «песочницу»:

1. **Проверка окружения**: Скрипт проверяет, примонтирован ли к целевой папке отдельный диск.
2. **Создание песочницы**: Если папка является обычной директорией, скрипт создаёт бинарный файл-образ (`.img` или `.vhd`) строго заданного размера.
3. **Безопасный перенос данных**: Если в папке уже лежали какие-то логи, они временно копируются в RAM/кэш, чтобы пользователь ничего не потерял.
4. **Монтирование**: Файл-образ форматируется в файловую систему (`ext4` для Linux, `NTFS` для Windows) и монтируется прямо в целевую папку. Старые данные возвращаются на место.
5. **Анализ и триггер**: Папка получает фиксированный объем. Скрипт считывает процент её заполнения. Если он не меньше заданного порога, запускается `find` + `sort`, отбираются **M самых старых файлов по дате изменения (mtime)**, упаковываются в сжатый архив (`.tar.gz`) в папку `backup_archives`, а оригиналы удаляются. Если архивация не удалась, исходные файлы не трогаются.
6. **Auto-Elevation (Удобство)**: Работа с дисками требует прав администратора. Скрипты `log_manager.sh`, `test_log_manager.sh` и `test_log_manager.ps1` снабжены модулем самоподнятия прав: если запустить их от обычного юзера, они сами запросят пароль (через `sudo` в Linux или UAC в Windows) и перезапустят себя.

**Windows (`log_manager.ps1`)** устроен проще: он работает с готовым диском (буквой тома).

1. Берёт путь, узнаёт букву диска и через `Win32_LogicalDisk` считает процент занятости **всего тома**.
2. Если процент не меньше порога, берёт M самых старых файлов (по `LastWriteTime`), упаковывает их встроенным `tar` в `backup_archives` и удаляет оригиналы (только если `tar` завершился успешно).
3. Изолированный диск фиксированного размера (VHD на 40 МБ с буквой `Z:`) создаёт не сам скрипт, а тест `test_log_manager.ps1` через `diskpart`. Поэтому на обычном диске (например `C:`) скрипт покажет занятость всего диска, а не одной папки.

### Параметры запуска основных скриптов

| ОС | Команда | Параметры |
|---|---|---|
| Linux | `./log_manager.sh <путь> <размер_МБ> <порог_%> <кол-во_файлов>` | размер диска-песочницы, порог, сколько старых файлов архивировать |
| Windows | `.\log_manager.ps1 -LogDir <путь> -Threshold <порог_%> -M_Files <кол-во_файлов>` | путь на диске, порог, сколько старых файлов архивировать |

## 🚀 ИНСТРУКЦИЯ ДЛЯ LINUX (UBUNTU)

### 1. Подготовка файлов
Убедитесь, что оба скрипта (`log_manager.sh` и `test_log_manager.sh`) лежат в одной папке. Дайте им права на выполнение в терминале:
```bash
chmod +x log_manager.sh test_log_manager.sh
```

### 2. Запуск автоматических тестов
Запустите тестовый скрипт. Он сам сделает всю грязную работу, запросив пароль администратора:
```bash
./test_log_manager.sh
```

### Что произойдет при запуске теста:
1. Создастся виртуальный диск на **40 МБ**, примонтированный в папку `./test_log`.
2. **ТЕСТ 1 (Порог 99%)**: Скрипт создаст два тяжелых файла по 9 МБ с датой изменения «5 дней назад». Диск заполнится примерно на ~60%. Скрипт сравнит 60% и 99%, поймет, что паниковать рано, и **пропустит архивацию** (файлы останутся на диске).
3. **ТЕСТ 2 (Порог 50%)**: Скрипт снова проверит этот же диск. Увидит занятость 60%, которая теперь **выше** порога в 50%. Он мгновенно упакует эти файлы в папку `./backup_archives` и очистит виртуальный диск (занятость упадёт до ~1%).
4. После каждого теста печатается `[PASS]`/`[FAIL]`, в конце — итог. Код возврата теста: `0` — всё прошло, `1` — есть провалы.
5. Окружение **нарочно останется примонтированным**, чтобы продемонстрировать работоспособность утилиты.

### Useful команды для демонстрации (в Linux):
* Посмотреть, что папка реально стала диском на 40 МБ: `df -h ./test_log`
* Посмотреть созданный архив логов: `ls -lh ./backup_archives`
* **Полная очистка системы после сдачи**:
  ```bash
  sudo umount ./test_log && sudo rm -rf ./test_log ./test_log_disk.img ./backup_archives
  ```

## 🏁 ИНСТРУКЦИЯ ДЛЯ WINDOWS (POWERSHELL)

### 1. Подготовка окружения
Запустите PowerShell **от имени Администратора** (Правой кнопкой мыши по пуску -> Терминал (Администратор) или PowerShell (Администратор)).

Разрешите выполнение локальных скриптов в сессии, если они заблокированы политикой Windows (ошибка «файл не имеет цифровой подписи»). Это действует только до закрытия окна. Сам тест запускает `log_manager.ps1` в отдельном процессе с `-ExecutionPolicy Bypass`, но если запускать `log_manager.ps1` вручную, эта команда нужна:
```powershell
Set-ExecutionPolicy RemoteSigned -Scope Process -Force
```

### 2. Запуск автоматических тестов
Перейдите в папку со скриптами с помощью команды `cd` и запустите тест:
```powershell
.\test_log_manager.ps1
```

### Что произойдет при запуске теста:
0. Если окно не от администратора, тест сам запросит UAC и перезапустится. Если буква `Z:` занята, укажите другую: `.\test_log_manager.ps1 -TestLog Y:`.
1. Через системную утилиту `diskpart` создастся и разметится виртуальный VHD-диск на **40 МБ** (файл `test_disk.vhd`). Ему автоматически присвоится буква `Z:`.
2. **ТЕСТ 1 (Порог 99%)**: Внутри диска `Z:` сгенерируются два файла по 10 МБ с датами «5 и 4 дня назад». Скрипт увидит занятость диска около ~76% (20 МБ логов плюс служебные данные NTFS), поймет, что порог 99% не превышен, и ничего не тронет.
3. **ТЕСТ 2 (Порог 50%)**: Скрипт зафиксирует превышение лимита, заберет оба файла, сожмет их встроенной утилитой `tar` в папку `.\backup_archives` и очистит диск `Z:` (занятость упадёт до ~25%).
4. После каждого теста печатаются проверки `[PASS]`/`[FAIL]` и итог.

### Useful команды для демонстрации (в Windows):
* Показать созданный архив: `Get-ChildItem .\backup_archives`
* Показать пустой/очищенный диск в проводнике или консоли: `Get-Volume -DriveLetter Z`
* **Полная очистка системы после сдачи**:
  ```powershell
  Dismount-DiskImage -ImagePath ".\test_disk.vhd"
  Remove-Item ".\test_disk.vhd", ".\backup_archives" -Recurse -Force
  ```
